## 训练主流程

入口：`train.py`。输入为已编码的 `train.bin` / `val.bin`；不是直接在训练循环读取原始文本。

1. 准备运行配置、数据访问、模型和优化器；模型可从新建、检查点或预训练分支得到。
2. 进入训练迭代容器，先设置本次学习率。
3. 满足评估间隔等条件时评估训练/验证损失；满足保存条件时写检查点。
4. 非仅评估退出时，进入梯度累积容器：取输入与右移一位的目标 → 模型预测并计算损失 → 按累积步数缩放损失 → 反向传播。预取下一批属于内部细节。
5. 按配置裁剪梯度，调用 scaler/优化器更新，再清理梯度。
6. 更新迭代计数，检查终止条件；未终止则回到迭代起点。

来源：`train.py:116`、`:216`、`:255`、`:286`、`:292`、`:300`、`:311`、`:314`。
验收时逐项检查：不能标成 epoch；不能套用“先 zero_grad 再 forward”的通用模板；不能把条件保存画成每轮必定保存。
实际更新可能受混合精度 scaler 状态影响，静态视图不能宣称每次调用都成功更新参数。

## 模型架构

默认阅读路径：

```text
token ID + 位置信息
        ↓
token 向量 + 位置向量 → Dropout
        ↓
上下文处理 Block × N
        ↓
最终归一化 → 词表预测分数
        ├─ 有目标：交叉熵损失
        └─ 无目标：末位置预测，用于生成
```

展开 Block：归一化 → 因果自注意力 → 残差合并 → 归一化 → 前馈网络 → 残差合并。
来源：`model.py:94`、`:103`、`:118`、`:170`。
`N` 来自配置；不能把某个默认值当所有运行的层数。
token embedding 与输出 head 权重共享（`model.py:138`），须显示 Shared；不能解释为两套独立权重。
Flash Attention 与手写实现是实现分支，不是两层连续的 Attention。

## 生成流程

入口：`sample.py`。从检查点或预训练模型初始化 → 编码提示文本 → 循环预测并采样下一个 token → 解码并输出生成文本。
来源：`sample.py:35`、`:80`、`:87`、`:88`，`model.py:306`。
生成文本是用户结果，不能因使用 `print` 而隐藏。
训练进度日志、分隔线和调试打印默认折叠进所属任务；原始调用事实仍可查看。
不能只根据函数名识别外部 `print`，用户自定义同名函数必须保留其身份。
