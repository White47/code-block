# 可读图布局、可关闭标签与双语界面设计

日期：2026-09-19。依据用户对当前 Tk 桌面 MVP 的试用反馈。设计方向已确认：图采用预览方案 A；Settings 可在中文与英文间切换；“关闭”指 VS Code 式标签页 `×`，不是退出应用。

## 目标与边界

- 在常见桌面分辨率下，窗口初次打开时可见主要操作，不让标题栏因固定 `1440×880` 几何尺寸落到屏幕外。
- 图以从上到下的单列主线为默认阅读方向；小图尽量在一个视口内完整显示，大图保持文字可读并允许上下滚动。
- 打开的图、源码和 Analysis Issues 标签可像 VS Code 一样点标签上的 `×` 关闭；Project Overview 常驻。关闭标签不是退出应用或删除数据。
- Settings 提供 `Language`：`简体中文`、`English`。默认简体中文，选择立即生效、重启后保留。
- 保留源代码只读、静态推断、缓存与 SourceAnchor 语义；不改分析事实、源码名称或用户项目文件。

## 当前结构与取舍

应用入口是 `CodeVizApp`（`src/codeviz/ui/tkapp.py`）；图提示由 `src/codeviz/views/layout.py` 生成，`GraphCanvas` 把提示转换为 Canvas 场景。Canvas 已有纵横滚动条，但非层级布局把拓扑顺序映射到横向 `x`，且未绑定常用鼠标滚轮。`ttk.Notebook` 有主/侧两个容器，目前没有单标签关闭操作。`Settings` 只有占位文字。手动节点坐标在每项目 `ViewState.positions` 中，全局语言偏好不能混入该项目的分析缓存。

备选布局有 A（单列纵向）与 B（纵向主线、同级分支并排）；用户选择 A。中文实现可逐处硬改文案，或集中为键值目录；选择后者以支持切换、缺失项检查与未来扩展。标签关闭采用真正的标签 `×` 命中区和独立关闭动作，而非仅在页内放“关闭”按钮。

## 交互设计

### 1. 窗口与标签

- 启动时根据屏幕可用尺寸选择初始窗口大小与位置，常见 `1366×768` / `1920×1080` 屏幕不再因固定尺寸隐藏系统标题栏。系统窗口 `×` 和 `WM_DELETE_WINDOW` 仍负责退出整个应用；**不新增全局“退出”按钮**。
- `Project Overview` 为固定标签，没有 `×`。Architecture、Training Flow、Symbol/Data Flow Context、Problems 和源码文件标签的右侧都有可点击 `×`；图与源码在侧栏打开时也遵循相同规则。
- 点击标签正文只选择标签；点击其 `×` 只关闭该标签。关闭当前标签后选中同一 Notebook 的邻近标签，主 Notebook 至少剩 Overview。侧栏最后一个标签关闭时收起 Split 面板。重新打开同类图或文件能得到正常的新标签。
- 关闭时清理对应图/源码小部件及临时引用，并立即更新已持久化的 `open_tabs`；重启不会重新出现已关闭标签。保留分析缓存、注释和其他标签。`Ctrl+W` 可作为当前标签的辅助关闭入口，但不能关闭 Overview 或整个应用。

### 2. 纵向图与滚动

- Architecture、Execution、Symbol 和 Data Flow 的默认自动布局均为从上到下；`y` 随主阅读顺序增加，主要流程箭头指向下方。Architecture 的包含层级与 Execution 的控制顺序仍分别决定节点顺序；交叉关系保持其真实类型，不靠画面位置伪称执行顺序。
- 单列节点放在中央图区域的一个稳定阅读带中，不为了把大图塞进一屏而把节点文字缩到不可读。图高度未超过可用视口时以正常间距完整显示；超出时保留节点尺寸，提供纵向滚动条、鼠标滚轮和键盘 Page Up/Down。横向滚动只作为手动拖动后溢出的兜底。
- 调整窗口大小时重新计算视口中的居中/滚动范围，不重新分析源码；首次打开视图时从顶部开始。Canvas 的边线端点与纵向节点对齐，回环、反向关系仍视觉区分；视图超过预算仍按现有聚合/下钻策略处理。
- `ViewState.positions` 中用户手动拖动的坐标不静默删除。旧项目若已有横向手动坐标，可用图工具栏的“重置项目布局”清除**当前项目所有图的手动坐标**并采用 A；其他项目、打开的标签、注释和分析缓存不受影响。此范围与现有按项目保存坐标的数据模型一致。若既有坐标和新自动布局冲突，界面提示可重置。

### 3. 中文 / English

- Settings 页面提供可见的 Language 控件，选择 `简体中文` 或 `English` 后立即更新活动栏名称、按钮、标签、空状态、图例、Inspector 标题、状态栏及应用产生的提示。已打开图/源码、当前选择与滚动位置尽量保持；无需重新 Analyze。
- 初次使用默认 `简体中文`。设置保存在应用自身数据目录的独立、受限全局偏好文件；不进入被分析项目、分析缓存或每项目 `ViewState`。异常或未知语言值回退到默认，并向用户给出可理解的提示，不阻止打开项目。
- 真实文件名、类/函数/变量名、源码文本、SourceAnchor、诊断代码及第三方仓库内容保持原文。已知语义角色的展示名称可以本地化，但底层标识符及置信度不变。翻译缺失时回退英文，不渲染空按钮。

## 组件边界与数据流

`View Builder` 继续提供有限 `VisibleGraph` → 纵向自动布局只写 `layout_hints` → `GraphCanvas` 渲染、滚动与拖动；坐标不回写 `Code Graph` 或 `Semantic Graph`。标签关闭由 Tk 外壳维护 Notebook 与 `_graph_tabs` / `_source_tabs` / `_problems_tab` 生命周期，然后经 `AppController.save_layout` 更新每项目打开标签。语言偏好由独立的本地设置读写负责；展示层从同一个翻译目录读取文字，解析器与缓存模型不依赖语言。

## 失败处理、安全与非目标

- 项目正在分析时允许关闭标签或应用，不执行被分析代码；后台结果不能更新已销毁的小部件。
- 偏好文件不可写时仍可在本次运行中切换语言，并显示“未能保存设置”的提示；不影响分析或用户源码。
- 不做完整系统语言自动检测、机器翻译、翻译源码/诊断正文、无限画布缩放或重新设计整个桌面外壳。
- 不承诺所有 100 节点图都在一屏显示；一屏容纳以正常字号、实际视口高度与可读性为先。

## 验收与测试

1. `1366×768` 和较大屏幕打开应用，系统标题栏可见；Overview 常驻，图/源码/Problems 标签各自可通过标签 `×` 关闭；Split 最后一个标签关闭后收起，重新打开可用；关闭结果重启后不恢复。
2. 小型固定图呈单列向下，主要边从上指向下；高度可容纳时无需滚动。大型图可用滚轮、竖向滚动条与 Page Up/Down 从顶部读到末尾，不牺牲正常字号；窗口缩放后仍可导航。
3. 旧的手动坐标不静默丢失；“重置项目布局”只清除当前项目的手动坐标，生效后为方案 A，不触碰分析缓存、注释或其他项目。
4. 在 Settings 中中英互切，当前窗口的主要可见文字立即更新；重启保持语言；源码标识符与源码内容不被翻译。偏好损坏/不可写时有安全回退。
5. 新增纯布局/翻译/偏好单元测试、Tk 可用时的标签关闭与滚动交互测试，并运行仓库已有 Ruff、mypy、unittest、wheel 构建。用 nanoGPT 小图与长图做人工验收，记录仍需人工观察的显示效果。
