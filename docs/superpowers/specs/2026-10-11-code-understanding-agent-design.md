# 只读代码理解 Agent 设计

日期：2026-10-11（实施记录更新至2026-10-12）。状态：用户已确认并授权按设计实施；A基础合同、B1安全解析与B2缓存来源已完成本机门禁及独立复审，B3快照实现及两阶段复审通过，B4部分模块与隔离依赖探针正在接续。完整功能尚未交付，实际进度见 `docs/CODE_AGENT_PROGRESS.md`。

## 1. 用户目标

在现有 CodeViz PC 应用内，结合真实源码与静态分析，解释功能如何实现，展示细致的功能路径、条件、调用与数据关系，并提供可信的源码和图节点引用。支持自由提问以及可开启、关闭的侧栏。完成后交付配置、使用、验证与故障处理指南。

“功能分支”指业务功能路径、条件分支和异常路径，不指 Git 分支。模型可以主动补查相关代码，但首版仅具有有界、只读工具能力，不具备编辑、运行、安装、提交或终端权限。

## 2. 现有技术与复用边界

- 前端：React 19、TypeScript、Vite、React Flow、Monaco；桌面：pywebview；后端：Python 3.11+。
- 复用 Symbol Index、Code Graph、Semantic Graph、局部 View Builder、SourceAnchor、现有源码安全读取和导航。
- 现有 `DesktopBridge.search/get_view/get_inspector` 不直接暴露为模型工具：查询可能带界面状态变化，需在 Python 内以纯查询适配器复用底层能力。
- 普通前端 bridge 调用有 15 秒超时；Python bridge 有共享 RLock。模型请求必须是后台任务，锁内只获取短时状态或快照，不在锁内等待网络，不放进项目写队列。
- 不迁移桌面壳，不引入 Next.js 服务、Docker、向量数据库、云端应用服务器或完整 IDE 插件。

B1/B2已为ParsedFile绑定实际解析字节哈希，缓存版本升为analysis4/semantic3/schema1并保存hash、不保存AST/源码；旧版本在解码前要求重新分析，布局/注释保留。现有图仍可变，不能作为不可变Agent快照；B3需提供独立查询投影及分析代次绑定。解析前后项目指纹只是辅助，不能替代实际解析内容身份。

## 3. 开源选型

推荐 assistant-ui 的 React 聊天组件与自定义 runtime；样式贴合现有应用，不运行创建 Next.js 项目的脚手架。候选后端为 Pydantic AI slim，仅安装首版协议所需依赖，通过自有 ProviderAdapter 隔离 SDK。

首次接入前先验证：React 19 兼容性、自定义 runtime 的取消契约、本地 CSP、无 CDN、Windows PyInstaller 打包和无 API 时的离线启动。依赖锁定版本，保留 MIT 许可声明；不启用第三方云历史、遥测或上传功能。若兼容性验证失败，停止该依赖接入并报告具体替代建议，不悄悄扩大技术栈。

调研依据：

- https://github.com/assistant-ui/assistant-ui 与 releases：React 聊天组件、自定义后端，2026-10-10 可见发布。
- https://github.com/pydantic/pydantic-ai 与 releases：工具调用与结构化输出，2026-10-09 可见发布。
- https://github.com/AsyncFuncAI/deepwiki-open：参考功能文档和代码导览组织方式；不整体移植其 Web/API 部署。
- https://github.com/continuedev/continue：README 已声明停止积极维护，不作为新运行时依赖。

这些是公开代码和文档调研，不代表已完成安装、运行、性能或供应链安全验收。

## 4. 首版功能

### 4.1 三种入口

1. 图节点：解释此节点，初始上下文为选中节点及有界邻域。
2. 源码：解释当前函数或文件；读取已保存、获准的项目源码。
3. 自由提问：例如“文件保存在哪里实现？”“这个条件失败后走哪条路径？”。

首版依赖已有分析索引。未分析项目提示先 Analyze；Outdated 项目提示重新分析后再生成新解释；Partial 允许查询成功解析部分，并明确标出覆盖缺口。没有检索到关系不等于关系不存在。

### 4.2 回答结构

回答分为功能摘要、入口与前提、执行步骤、条件/异常/返回路径、调用与数据关系、证据、未确认事项。每个关键事实及关系关联证据编号；模型推断单独标识，不因有引用就升级为静态确认。

关系分别标记调用、控制、数据、结构；不将调用顺序解释为运行时必然顺序，不将静态数据关系等同实际 tensor 或 gradient 流。循环与递归给有限摘要，不无限展开。

没有可靠证据时回答无法确认并说明缺失，不编造路径、行号、节点或链接。首版不承诺自动恢复完整项目或所有动态调用。

### 4.3 聊天侧栏

- 在右侧面板提供“检查器 / AI 助手”切换，以及可发现的助手入口与关闭按钮，不取代源码标签页。
- 支持输入、流式文字、运行状态、停止、失败说明、显式重试、清空对话、新建对话、可点击证据卡片。
- 关闭面板请求取消当前任务，保留当前项目的内存对话；重新开启不自动请求模型。
- 切换项目取消在途任务，按项目与会话隔离对话；旧结果不可进入新项目。应用退出清除首版聊天与密钥，不承诺跨应用重启恢复。
- 最终结构化回答通过校验后才显示可点击引用。流式未校验文字不包含可执行导航动作。
- 关闭或停止只意味着停止本地后续工作、尽力取消网络请求，不保证服务商尚未产生的计费或计算能撤销。

## 5. 请求生命周期和只读工具

前端 → start 任务 → Python 后台调度 → 本地检索/安全片段 → 经授权的 API → 结果验证 → 聊天显示/现有导航。

任务状态为 Queued、Running、Completed、Cancelled、Failed、Stale。start 快速返回 jobId，同一 epoch 内的 requestId 幂等且对不同载荷拒绝复用，防止前端超时重发产生重复收费任务；poll 返回单调事件序号之后的有界事件；cancel 幂等。请求绑定 projectEpoch、analysisGeneration、对话与请求 ID、当前模型配置、获准读取范围。取消被后端确认后不再开始新的外传，已在网络中的请求只能尽力取消。

后台使用独立锁与有界事件队列，每项目同时一个任务。事件最大 256 条、每条最多 8 KiB；客户端落后时返回有界完整状态，不无限保留 token 事件。结束释放网络连接及任务资源；保留最多 10 个内存对话、每对话 40 条消息，对话与其证据注册表总量最多 2 MiB，最多 1,000 项证据。超限明确提示或裁剪最旧完整对话及对应证据，不隐式持久化源码。清空对话、撤销授权、服务地址切换会取消相关任务，清除相应证据并阻止旧历史重新外传。

工具白名单：

- `search_symbols`：项目索引中的限定名、类型、锚点和相关性，最多 20 个结果。
- `read_source_excerpt`：后端从获准文件读取有界片段，核验路径、句柄身份及快照一致性，不接受任意绝对路径。
- `get_local_relations`：从代码/语义图查询受限邻域，最多 2-hop、50 节点和 100 条关系；截断显式返回。

每次提问最大 2,000 字符、最多 8 个文件、累计最多 12,000 字符源码、8 次工具执行、6 次模型请求；输入 token 总预算 20,000、输出 token 总预算 2,000、总时限 90 秒。预算包含协议重试；token 使用按服务商统计和本地估计说明，不伪报精确费用。任何预算用尽保留已获证据并明确标记不完整，不能绕过上限继续重试。默认历史只附带最近 6 条消息并受相同总预算限制。

文件数计不同文件；源码字符数计每次外传的累计量，包括重复片段与历史。搜索元数据、关系、工具结果、修复和重试均计入 token 总预算。发送前预留预算，关闭 SDK 隐式重试；未知 tokenizer 时以 UTF-8 字节数加协议开销作保守上界，无法界定则拒绝发送，不把 SDK 单请求限制误当全任务限制。

## 6. 可信引用合同

证据由本地程序签发 opaque evidenceId，映射到 projectEpoch、analysisGeneration、文件内容哈希、SourceAnchor、可选 symbolId/codeEdgeId/semanticId、原有 confidence 与截断信息。模型只能引用本请求中提供的 evidenceId。

后端先校验结构、证据归属、锚点范围、节点存在性与关系支持，再产生安全 DTO。不存在/越权/过期引用没有可点击动作，返回明确验证问题；有界修复尝试计入任务预算，最终仍失败时显示失败说明，不伪造成功回答。

关系端点、类型和原 confidence 由后端确定，而非采信模型字段；合法证据只证明引用有效，不证明任意自然语言说明正确。业务用途、作者意图和超出静态证据的顺序始终标记为 AI 解释。

片段读取使用 Python 源码编码规则，SourceAnchor 的行号为 1-based、结束行包含；Python AST 列为 0-based UTF-8 字节偏移、结束列为排他边界，导航到 Monaco 前转换为其 1-based UTF-16 列坐标，缺少列则定位整行。拒绝倒置、越界或落在非法字节边界的范围。安全句柄读取前后核验内容身份，截取后签发证据；不将现有返回全文的 read_source 直接注册为模型工具。

源码动作由本地导航构建，不渲染模型生成的任意文件 URI、URL、HTML 或应用命令。图中定位复用现有 RevealTarget 与局部上下文；源码片段可能没有可定位图节点，这时仅提供源码引用并解释原因，不能发明节点。

LLM 解释与建议关系保存在独立响应对象，不修改 Code Graph、Semantic Graph、Visible Graph、布局、分析缓存或既有 confidence。用户点击定位可以切换局部视图，但不自动重画主图。

## 7. 源码版本与编辑保护

首版读取磁盘已保存内容，不读取、上传、保存或丢弃 Monaco 未保存草稿。前端在发起及阅读结果时提示相关 dirty 状态；存在相关 dirty 时不得声称解释反映当前编辑内容，用户先自行保存并重新分析才能获得最新分析解释。

源片段读取时与分析快照指纹核验；结果完成和引用点击前再次检查查询依赖集合，无法界定依赖时核验整个已分析文件集合，并显示核验时点。变化、改名、删除、重新分析或项目切换使该请求变为 Stale；旧解释仍可阅读，但禁用过期引用并提示重新分析。不得根据陈旧行号跳转到未经核验的代码。

每次模型外传前、接收工具请求时、完成与导航时核对 epoch/generation/cancel 状态。迟到结果被丢弃，不串项目。外部文件变化可能在请求期间发生，不能承诺已经发送的片段被撤回。

fresh 核验同时比较分析文件集合，检测新增或删除的可分析文件，不仅对旧集合逐个检查哈希。

## 8. API、授权与安全

### 8.1 配置

首版仅支持一种 OpenAI-compatible chat/tool 协议，提供 Base URL、模型名、API key、无源码连接测试及预算显示。兼容协议不代表所有服务商均支持工具或结构化输出；测试报告具体兼容错误，不擅自降级为无引用普通聊天。

API key 在前端输入期间短暂存在，提交后立即清空输入；首版长期仅存 Python 内存，getter 只返回是否已设置；不回传前端、不存 localStorage、项目文件、日志、提示词或分析缓存。非敏感服务地址和模型名可保存到应用设置；跨重启需要重新输入 key。退出释放引用，不承诺物理内存安全擦除。系统凭据库持久化属于后续独立能力。

首版仅允许用户明确确认的 HTTPS 服务地址，拒绝 URL 内凭据、query 与 fragment；限制请求到确认的 origin 与固定协议路径。禁用自动重定向，不让模型改变服务地址，不关闭 TLS 校验。API 通信仅由 Python 发起，保持前端 connect-src 限制。本地 HTTP 模型另行设计授权，不在首版例外开放。

### 8.2 外传授权

默认关闭 AI；仅明确点击启用和发送请求才允许外传。首次展示服务商/地址、模型、发送内容类别、允许的项目文件范围与上限，授权按项目+服务地址保存于当前内存会话；范围扩大或目标改变重新确认。

模型工具的读取范围为当前项目内、排除 Ignore Paths 后的已分析文件集合与用户外传白名单的交集，再排除受保护路径；`.env`、密钥、证书、Git 内部和其他受保护路径拒绝。片段脱敏遇到疑似凭据则阻止该片段外传并提示，不能宣称自动脱敏完全可靠。模型可检索本地元数据，但元数据外传同样受授权约束。

源代码注释、文档和模型输出均是不可信数据，不作为工具权限或系统指令。工具执行的安全规则独立于提示词；禁止 shell、执行/导入项目、任意网络、源码和资源管理器写操作。渲染不启用 raw HTML，外部 Markdown 链接不自动打开。

不得把整个 DesktopBridge 方法列表暴露给模型，也不允许模型控制保存、删除、改名、移动、项目选择或窗口退出保护。

现有 SECURITY_AND_PRIVACY 的“不上传源码”需在实施阶段明确增加“默认不上传，用户主动授权 AI 请求时仅上传批准片段”的例外，并在 PRD、UX、缓存与限制文档同步，不让文档长期冲突。

## 9. 故障处理

区分未配置、缺少分析、分析过期、授权不足、片段阻断、鉴权失败、额度/限流、协议不兼容、网络超时、证据校验失败、任务取消和预算耗尽。错误不含 key、请求 headers 或完整源码。默认不自动重新发送有费用的请求；重试由用户主动触发并重新核对范围。

AI 出错不影响现有分析、编辑、标签页、缓存和文件管理。未安装 AI extras 时能启动和使用原功能；没有 key 时不发请求。退出沿用既有未保存草稿保护，退出通过后取消 AI 并释放资源。

## 10. 验收与交付

- 文件保存示例：说明入口→验证→冲突分支→写入→结果；关键步骤都有真实、可点击证据，猜测独立标记。
- 通用 Python fixture：CLI 条件分支、递归、跨模块调用、异常与动态未解析；ML fixture：nanoGPT 风格模型/训练，不能仅支持训练代码。
- 对伪造 evidenceId、越界路径、受保护文件、恶意注释、HTML、过期哈希、迟到跨项目结果和超预算工具请求，拒绝权限或可执行引用。
- 关闭/重新开启、停止、切项目、编辑冲突和网络失败不冻结 PC 窗口、不丢草稿、不产生隐式新调用。
- 用 fake provider 做确定性自动测试，不在 CI 调用收费 API或保存秘密。真实 API 的验收由用户提供配置并主动授权。
- 运行 Python Ruff/mypy/Linux typecheck/unittest、前端 lint/typecheck/Vitest/build；验证源码、wheel 隔离安装和最终 EXE。分别报告 pass/fail/skipped 与原有警告，不用浏览器测试冒充桌面测试。
- 独立 reviewer 审查权限、版本与引用事实，而非只看测试通过。

交付时提供新版 PC 启动位置、依赖/运行环境、API 配置步骤、外传说明、开启/关闭/停止、节点/源码/自由提问示例、引用验证、常见错误处理。下一步建议根据实际体验决定：跨重启对话/系统密钥库、本地模型适配、更丰富关系解释或人工确认的解释叠层；不自动进入写代码 Agent。
