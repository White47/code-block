# 交互式源码画布设计

日期：2026-09-19。依据用户对当前桌面 MVP 的试用反馈及已确认的 A+B 混合方案：主流程使用纵向图，双击单个节点或点击 `+` 后，在附近空白区域展开可拖动的“细节岛”。技术路线选择增强现有 Tk Canvas，不嵌入完整 draw.io 或 WebView。

## 目标

- 将 Architecture、Execution、Symbol 和 Data Flow 从静态图升级为可平移、缩放、局部展开的二维源码画布。
- 主图保持从上到下的清晰阅读顺序；查看节点内部信息时不替换主图、不丢失上下文。
- 每个主节点和细节节点都能通过 Inspector 或独立动作准确打开真实源码。
- 借鉴 draw.io 的图模型、分层布局、避障连线、稳定标识和折叠状态，但保留现有 Python 标准库技术栈与分析边界。

## 已确认的交互模型

### 主画布

- 主流程采用分层纵向布局：入口在上、结果在下，同层分支向左右排列，汇合节点尽量回到主阅读轴。
- 画布支持拖动空白区域平移、滚轮缩放、适应窗口和恢复 100%。长图仍可使用滚动条与 Page Up / Page Down。
- 单击节点只执行选择、邻居高亮和 Inspector 更新，不自动改变图结构。
- 双击节点或点击节点上的 `+` 展开细节岛。键盘 Enter 与双击保持同一语义；Open Source / Open to Side 继续是独立动作。
- 用户拖动主节点后保存其位置；重新分析或重新布局时优先保留仍可匹配 Stable ID 的手动位置。

### 细节岛

- 细节岛是主画布上的局部子图容器，在被选节点附近最近的可用空白区域创建，并用弱化虚线连接回来源节点。
- 岛内只展示目标节点的内部组件、关键数据与解释该节点所需的一跳关系；查询使用现有 Graph Query / View Builder，不直接读取 AST。
- 岛可拖动、关闭，标题显示易读名与真实代码名，并提供 Open Source。关闭只移除视图状态，不改变分析结果。
- 同时最多保留三个细节岛。达到上限时不静默关闭旧岛，而是提示用户先关闭一个。
- 岛内节点可单击并在统一 Inspector 中查看，也可打开源码；首版不允许从岛内继续嵌套生成新岛，避免无限递归和视觉失控。
- 细节查询失败只在该岛显示明确错误，不清空主图；没有可展开内容时保留选择和源码动作，不生成空岛。

## 场景模型与组件边界

现有数据流保持不变：

```text
Code Graph / Semantic Graph
  → Graph Query / View Builder
  → Visible Graph
  → Canvas Scene
  → Tk Canvas
```

新增 UI 专用 `Canvas Scene`，将一个主 Visible Graph 与零到三个局部 Visible Graph 转换为可绘制元素：

- `SceneNode`：Stable ID、边界框、显示文字、样式、选择状态和 SourceAnchor 引用。
- `SceneEdge`：起终点、关系类型、路由点、箭头与弱化状态。
- `DetailIsland`：岛 ID、来源节点 ID、局部图、位置、尺寸和关闭状态。
- `Viewport`：zoom、pan、可见边界及适应窗口计算结果。

Canvas Scene 是投影，不写回 Code Graph 或 Semantic Graph。`GraphCanvas` 负责绘制与输入事件；Controller 负责查询、限制、源码导航和持久化请求；View Builder 继续决定哪些节点可以进入界面。

## 布局与连线

- 首次布局使用确定性的 layered / hierarchical 策略，以拓扑层级或控制顺序计算纵向 rank。
- 同 rank 节点依据父节点、边交叉数量和 Stable ID 稳定排序；布局结果必须可复现，不能使用随机坐标。
- 分支优先左右对称展开，汇合节点位于前驱重心附近；循环和递归使用回环边，不重复生成节点。
- 细节岛放置按右、左、下、上顺序搜索空白矩形，并考虑当前视口、主节点、其他岛和画布边距；没有足够空间时扩大场景边界，而不是覆盖主节点。
- 边采用端口到端口的正交或平滑折线路径，至少避开节点边界。Data Flow、Calls、Control Flow、Loop、Gradient Flow 与 Contains 保持不同颜色、线型或箭头，并由图例说明。
- 用户手动位置高于自动布局；“重置项目布局”清除主节点和细节岛的手动位置，但不删除分析、展开状态、标签或注释。
- 布局算法异常时退回简单纵向排列并记录 Analysis Issue，不阻止源码导航。

## 缩放、平移与坐标

- 场景坐标与屏幕坐标分离：`screen = scene * zoom + pan`。命中测试、拖动、边路由和新岛放置使用场景坐标。
- 缩放以鼠标指针所在场景点为锚，建议范围为 25%–250%；低缩放下可弱化次要文字，但不得改变图语义。
- 拖动空白区域平移；拖动节点或岛移动对象。通过按下目标和最小移动阈值区分点击、节点拖动与画布平移。
- “适应窗口”只改变 Viewport，不重写节点位置；“100%”恢复 zoom，尽量保留当前视图中心。

## 源码追踪与置信度

- 所有可交互节点必须维持 `Visual Node → Semantic Component → Code Symbol → SourceAnchor` 链路；纯分组容器可以没有源码，但必须列出其成员来源。
- Inspector 展示易读名称、真实名称、类型、语义角色、Exact / Probable / Unresolved、判断依据、关系和源码范围。
- 动态调用只显示可能目标，不将候选伪装为 Exact。SourceAnchor 不可用时节点仍可查看，但 Open Source 禁用并显示原因。
- 分析变为 Outdated 后允许继续浏览旧图，画布显著标记状态；重新分析后按 Stable ID 恢复仍存在的节点、岛来源与位置，无法匹配的状态被安全丢弃。

## 状态与持久化

View State 扩展但继续与 Analysis Cache、Annotations 分离，至少保存：

- 每个视图的主节点手动位置；
- viewport zoom / pan；
- 已展开细节岛的来源节点、位置和关闭状态；
- selected node、expanded / collapsed、filters 与 open tabs。

不保存完整源码或 Tk item ID。恢复时必须校验类型、数量和有限数值；损坏、超大或引用失效的视图状态按字段降级，不能阻止项目打开。

## 性能与可访问性

- 主 Visible Graph 默认保持几十至约 100 个节点；细节岛各自使用更小预算，且总数最多三个。
- 平移和缩放不得触发源码重新分析或 Semantic Graph 重建；只重绘当前 Scene。
- 边路由可以缓存，并在关联节点、岛或布局变化时局部失效。
- 节点保持可读字号和足够点击区域；选择、关系类型和置信度不能只依赖颜色。
- 键盘支持节点焦点、Enter 展开、Escape 关闭当前岛，以及既有 Open Source 动作。

## 安全、失败处理与非目标

- 保持静态分析、源码只读、不执行项目代码、不导入目标项目或第三方框架。
- 不把完整 draw.io、浏览器运行时或 WebView 加入 MVP；不下载远程布局服务，不向外上传源码或图数据。
- 首版不做自由绘图、用户新增任意节点、多人协作、无限嵌套细节岛、完整图编辑器或实时增量索引。
- `.drawio` 导出是独立后续能力；若实现，只从已脱敏的 Visible Graph / Canvas Scene 生成，不反向成为分析事实来源。

## 验收标准

1. Architecture 与 Execution 主流程按从上到下显示，常见分支和汇合连线清晰；大图可平移、缩放和适应窗口。
2. 单击节点只更新选择、邻居高亮和 Inspector；双击、Enter 或 `+` 在最近空白区域打开细节岛，主图不被替换。
3. 最多三个岛可以同时存在、拖动和关闭；达到上限有明确提示；岛内不能无限嵌套。
4. 主节点和岛内节点都可准确打开源码；不可定位、Probable 或 Unresolved 情况如实呈现。
5. 节点、岛、zoom 和 pan 在重启后恢复；重新分析时按 Stable ID 保留可匹配状态，损坏状态安全降级。
6. 100 节点预算内交互保持可用；布局或单岛失败不清空主画布，也不阻断源码查看。
7. 原有 Architecture、Training Flow、Search → Reveal → Inspector → Source 三条黄金路径继续通过。

## 验证策略

- 纯单元测试：场景坐标转换、层级 rank、稳定排序、岛空白放置、上限、边样式、状态序列化与损坏输入。
- Tk 交互测试：点击/双击区分、`+`、拖动、平移、指针锚定缩放、适应窗口、岛关闭和源码动作。
- 回归测试：现有 View Builder 预算、Inspector、Search Reveal、布局重置、标签关闭、双语和 Cache / Outdated 行为。
- 人工视觉验收：小型分支图、长训练流、循环/递归、多岛避让、中文长名称与高 DPI。
- 每个实施阶段继续运行 Ruff、mypy、完整 unittest 和 wheel 构建，并区分既有平台跳过与新增失败。
