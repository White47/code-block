# DeepSeek bounded stream and source-free connection design

## Scope and decision

Continue the approved local-JSON-validation capability and SDK wire profile.
Goodall's architecture review selected three bounded tasks: stream validation,
source-free connection protocol, then private runtime injection. No dependencies
or production activation. Generic strict behavior remains supported unchanged.
AGENTS.md governs autonomous execution; no routine confirmation is required.

## Stream contract

Select DeepSeek framing only through the private SDK wire profile. Each JSON
chunk has exactly one choice, index 0. Non-null usage is allowed at most once,
on the terminating stop/tool_calls choice. After termination accept only allowed
SSE comments and DONE; reject empty-choice usage, premature/duplicate usage,
additional JSON, incomplete EOF and nonempty reasoning. Preserve existing
UTF-8 framing, raw/generated byte caps, tool-fragment bounds, deadline,
cancellation and cleanup ownership. Do not weaken the generic decoder.

Token counts (primary, total, cache and detail counters) are exact nonnegative
integers no greater than the accounting safe bound 2**53-1; output
must not exceed allocation. Cache details do not add to input again. Missing
or null usage on normal termination remains unknown, never SDK-default zero.
Existing sticky accounting blocks final preparation after unknown tools usage;
unknown final usage preserves the existing validated-result/warning policy.
Malformed usage is a protocol failure, not a fabricated estimate or zero.
Comment frames must contain at least one actual colon-prefixed line. Bare empty
LF/CRLF frames are rejected on this closed DeepSeek path, including before and
after DONE. Generic framing and its previous numeric bound remain unchanged.

## Trusted connection binding

Add frozen/slots TrustedConnectionProfile(profile_id, endpoint, model, protocol)
in connection_profile.py. Only the closed DeepSeek profile and protocol
deepseek-json-object-v1 are accepted. Validate exact types, copy primitives and
freeze application-owned injection. An estimated-input profile, request body or
provider self-report cannot select output capabilities. Default None/empty
injection follows existing strict behavior. Reject duplicate matches, mismatched
configuration and mutation before entering the provider transport.

run_connection and _validate_prepared gain keyword-only connection_profile=None.
The runner freezes binding before provider creation and checks it again before
send. Accounting profile equality is a consistency check, not capability trust.

## Fixed probe and events

connection_draft/connection_stage logical bytes stay unchanged: Call p. with
empty-object tool schema, then Return {}. with the same closed empty-object
schema. No project identity or caller/source text enters either probe. Extract
a pure _probe_json_instructions helper shared by SDK and connection validator.
DeepSeek final wire messages consist exactly of its fixed JSON system prompt,
empty-object example, and original user message. Require disabled thinking,
include_usage, max_tokens and json_object; tools omit remote strict. Occurrences
remain empty and provenance complete. Reject extra or different wire fields.

For the fixed final probe only, the SDK accumulates text without provisional
text events and publishes the existing answer/usage events after successful
stream termination. Do not loosen _read_tools or _read_final. Validate exactly
one p({}) and strict local {} before publishing ConnectionCapabilities with
structuredOutputSupported=false, jsonObjectSupported=true and local-json-schema.
No repair, provider fallback or beta endpoint.

### Probe allocation correction (architecture decision, 2026-10-22)

The real SDK exposed a pre-existing contradiction: the old tools allocation 32
cannot contain even the shortest normalized p({}) event (36 bytes including
framing). Do not subtract framing or enlarge the cumulative budget. Goodall
reviewed and main selected DeepSeek-only tools=96, final=32, still total=128.
Generic strict remains tools=32, final=96 and its existing assertions unchanged.
Fixed logical probe bytes/schema remain unchanged. Explicit trusted connection
binding chooses draft allocations; the SDK accepts the corresponding allocation
only through its validated private wire profile, never request metadata. Cross-
profile allocations are refused, not accepted as alternative valid envelopes.

For unescaped ASCII IDs the normalized tool event uses 35+ID-byte-count bytes;
96 allows at most 61 ID bytes (64 would allow only 29). This is a bounded support
limit, not a claim about live provider ID lengths. Escaped/longer IDs and final
output exceeding 32 remain budget errors. Test exact limits, unknown usage,
unchanged cumulative 128 and the successful actual-SDK two-probe path. New test
fixtures identify tools by the tools field, not by the now profile-specific
numeric allocation; fixed-final reader reservations use 32 for this profile.

## Private injection

AssistantService gains trusted_connection_profiles=(); _AssistantRuntime gains
trusted_input_profiles=(), trusted_connection_profiles=(). Validate and copy at
construction; propagate both through _ensure_engine. _work_connection chooses
the unique trusted binding for its frozen job endpoint/model. Existing config
guards remain authoritative; no provider-controlled profile registration.
Desktop construction remains default OFF. Production assembly, real transport
activation, packaging/native acceptance and live API testing are later tasks.

## Evidence and limitations

Use the existing pinned SDK with in-memory SSE transport and socket/DNS guards.
Prove each original request enters transport once; usage/unknown, hostile frame
ordering, chunk splits, cancellation, config mutation and disposal remain safe.
Test runtime -> connection -> SDK -> fake SSE -> local capability/retirement.
Run only touched modules/direct consumers during tasks; one independent phase
review and the AGENTS.md final gates at the boundary. Unchanged frontend evidence
is reused. Optional dependency/native skips are not passes. No paid requests,
credentials, source upload, dependency install, commit or push.
