# 任务契约模板

两种用法，按需要选一种：

- **自主模式**（推荐，日常主线）：给一条规则 + 一个边界，它自己把队列跑完。
- **单任务模式**：给一个任务，它做完就停。适合改一处、验证一个想法。

---

## 一、自主模式

只在开头说一次，之后不用再管。

```
按 AGENTS.md 的 Execution mode 走自主模式。

队列：docs/superpowers/plans/<计划文件>.md
起点：docs/CODE_AGENT_PROGRESS.md 里的当前断点
边界：<跑到哪里停，例如：Task5 收尾 + Task6 阶段末复审完成>

要求：
- 每个任务在对话里只留一行进度，不改进度文件
- 只跑受影响模块和直接消费者的测试
- 全量测试 / 跨平台 mypy / 独立复审只在边界各做一次
- 不用问我"要不要继续"，到边界再汇报
- 遇到需要我决策的事（改公共契约、加依赖、改或删测试、验收标准有歧义）
  停下来，只说三件事：哪个任务卡住 / 需要什么决定 / 你默认会怎么做
```

启动后不要打断它。它到边界会自己汇报。

**边界怎么写才好用**：

| 写法 | 效果 |
| --- | --- |
| `边界：Task5 收尾，然后停` | 只推一个任务 |
| `边界：Task1–Task5 全做完` | 推一段 |
| `边界：推到 C3 阶段末（Task6 复审完成）` | 推到阶段边界，推荐 |
| `边界：把 C3 剩下全部做完，到 C4 前停` | 跨阶段，token 风险较高 |

队列里的任务粒度越清楚，它跑得越稳。`publication` 计划和 `runtime` 计划都已有 `### Task N` 分节，可以直接引用。

## 二、单任务模式

需要精确控制范围时用。

```
任务：<一句话，只说结果>
验收：<一个可观测的结果，例如 tests/test_x.py 的 3 个用例通过>
范围：只允许修改 <文件列表>

规则：
- 不派发 reviewer / architect / final_auditor 子代理
- 不加载 subagent-driven-development 或 executing-plans
- 只跑 <相关测试文件>，不要跑全量
- 做完就停，不要开始下一个任务
- 不要更新 docs/CODE_AGENT_PROGRESS.md
- 完成后只回 5 行：改了什么 / 跑了什么 / 结果 / 遗留风险 / 建议的下一步（只建议，不要执行）
```

## 如何切换到新规则

### 前提：新规则只在「新会话」生效

`AGENTS.md` 和 `.codex/` 都是**会话启动时读取一次**的。
正在运行的那个会话不会自动重载，上下文里还压着整段旧行为。

所以：**开一个新会话**（Codex CLI 用 `/new`，桌面版新开一个对话）。

### 旧会话的收尾话术（直接粘贴）

```
停止当前动作。

仓库执行规则已改，写在根目录 AGENTS.md 和 .codex/agents/ 里。
先重新读取 AGENTS.md，然后严格按新规则执行。

新规则要点：
- 复审只在阶段边界、触及语义核、或同一缺陷修两次仍不对时做，同一个 diff 只审一次。
- 只跑受影响模块和直接消费者的测试。全量只在阶段末尾跑。
- 已通过的代码快照不因新增测试而作废，不要重跑全量。
- 每完成一个任务只留一行进度，接着做下一个，不要问我要不要继续。
```

### 即时叫停话术（它跑偏时）

- 「停。不要跑测试。只回答三件事：当前改动、当前失败项、下一步一句话。」
- 「不要复审，不要跑全量，直接改到 GREEN 就停。」
- 「你违反了 AGENTS.md 的 Review policy 和 Test scope。停止额外复审，只报告当前状态。」

连续两次不听，直接中断进程（Esc / Ctrl+C），开新会话重来。

## 怎么看它有没有正常跑

**健康迹象**

- 每个任务一行进度，连续往下走，不回头重跑全量
- 只在边界出现较长汇报
- 只在需要决策时停

**不健康迹象（该叫停）**

- 又开始每个任务派 `reviewer`
- 又在重跑全量或跨平台 mypy
- 长时间不出进度行，卡在某个测试上反复重试
- 开始给你写长篇报告或逐条复述计划

确认它读了新规则：根目录 `AGENTS.md` 的修改时间应是 **2026-10-15 17:00 之后**，
并且内容里含 **Execution mode** 一节。没有就是没读到。

## 顺手可做的加固

`<user-home>\.codex\AGENTS.md` 目前是**空文件**。
把 `AGENTS.md` 里的 **Test scope / Execution mode / Model tiering** 三段写进这个全局文件，
所有项目都会生效，不必每个仓库配一遍。
