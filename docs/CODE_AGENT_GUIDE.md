- 切换项目和退出仍使用保存/放弃/取消保护；取消切换不能破坏草稿或当前聊天。强制结束后不恢复 AI 会话和密钥。

内存最多 10 个会话、每会话 40 条消息，并受总容量和任务上限约束；不将聊天、密钥或源码正文写入分析缓存或偏好。

## 常见错误

配置/禁用错误：核对地址、模型、密钥、启用状态。鉴权/限流：确认服务商权限和额度后手动处理。依赖缺失/门禁关闭：等待门禁与打包验收，不通过换地址或安装 SDK 绕过。分析缺失/过期：显式重新分析。未授权/源码被阻止：核对项目和精确允许范围。

协议校验失败不能直接解释为服务商缺少能力。证据失效或结果不可用：不把临时文本当作结论，缩小范围重新解释。预算/请求/容量限制：缩小范围或清理会话，不调大硬上限掩盖失败。网络/桥接超时：先判断是否恢复原请求，避免盲目重发。

输入预算栏显示的是**此前已经准入的累计预留量**，不是刚刚被拒绝请求的大小。
历史任务例如显示3475/20000时，下一轮携带检索结果的预估若超过剩余16525，仍会报预算拒绝，
且不会把被拒绝的下一轮加进上方计数。界面现在明确说明“下一次请求”被阻止。
估算与服务商报告的实际tokens不是同一计数口径；不能通过相减两者判断是否还允许后续请求。

检索现在会按预算保留完整事实及其来源，超出范围的内容只留下省略数量与覆盖缺口，
不会截断来源证明或让被省略的内容成为可引用证据。系统提前为最终答复保留输出额度，
必要时结束继续检索并明确标注分析不完整。本轮按用户授权将新解释任务提高到累计输入估算100,000、
输出预留8,192；DeepSeek专用组装最多4轮普通检索、10次模型请求、16次工具调用（包含初始搜索）、180秒。
普通单次512，最终答复4096，一次完整结果的格式修复2000；三者最坏预留8144。通用默认仍为8轮普通检索、final/repair各2000。配置化阶段剩余额度不足时直接拒绝，不生成缩小的阶段额度。
新任务用量栏显示100,000输入上限及8,192输出上限，历史任务保留当时额度，不自动重发失败请求。
连接检查仍为原来的1,024输入/128输出/15秒；8文件、累计12,000源码字符和单片段4,000的读取约束不变。
这属于发送前规划，不能保证每个项目都能完整覆盖；最终请求仍须通过原有预算及来源校验。
