# 安全与隐私

## AI 权限例外与当前门禁（2026-10-20）

默认本地分析、不上传、不执行。只读助手只有在生产门禁放行、用户启用个人配置、明确批准当前项目的精确文件范围并主动发送后，才可向选定服务商发送批准的已保存代码片段、允许的元数据和会话上下文；不含编辑草稿。模型文本及源码注释均为不可信数据，不能授予工具/文件权限、修改源码或执行代码。配置、授权、打开/重开侧栏不自动调用模型。

密钥仅内存保存，不回传正文、不写日志或 Git；项目、配置、授权、会话修订和源码身份均需重新核验。取消回执不等于后端确认与资源释放。当前源码生产组装仅准入 DeepSeek 专用配置，启动仍禁用、无密钥；安装 SDK、配置或授权均不自动发送。真实 API 与本轮原生交付尚未验收；详见 [助手指南](CODE_AGENT_GUIDE.md)。下方旧“不上传”条目描述默认离线模式，不替代此显式授权例外。

- 默认只读分析，不执行用户源码，不导入运行时副作用。
- 分析与查看不修改用户源码、不上传源码；用户批准显式源码编辑保存及项目资源管理器操作。保存仅写当前项目内安全校验的既有文本；新建、改名、树内移动和回收站删除必须由用户显式触发，不能覆盖已有目标或执行源码。移动仅限当前项目内同卷 no-replace rename；没有跨项目、外部拖入、复制后删除或自动 import 修复。编码、版本冲突与未保存退出保护见 [源码编辑合同](SOURCE_EDITING.md)；目录权限、版本与回收站边界见 [资源管理器合同](PROJECT_EXPLORER.md)。缓存仍放应用自身数据目录。
- 不保存完整源码副本；SourceAnchor 只保存路径与范围，展示时读取真实文件。
- 第三方库默认 External Node，不深入扫描整个依赖树。
- 用户可配置 Ignore Paths；默认忽略 `.git`、虚拟环境、node_modules、缓存、构建目录、模型权重、数据集、二进制。
- Runtime Trace、真实 tensor shape、autograd graph 只能作为后续用户主动触发的能力，并需单独权限与告知。
- 解析不可信源码时限制资源、处理异常、避免路径穿越和符号链接越界；错误必须隔离。
- Phase 8 源码查看先校验项目相对 SourceAnchor 与解析后的路径，再按已打开的文件句柄核对最终路径和文件身份，防止检查与读取之间的链接替换；无法在当前平台安全核验时拒绝读取。
- Phase 10 的源码指纹读取复用已打开句柄核验；缓存是有大小上限的白名单 JSON，不保存 AST / 完整源码，不使用 pickle 或任意类导入，写入经同目录临时文件原子替换。缓存目录如果解析到被分析项目内则拒绝写入。缓存损坏不能清除独立的视图状态或标注。
- 第三方语料验证只读取固定提交源码，不安装 / 导入 / 执行目标仓库。验证报告不得包含完整源码或任意 Full Graph；输出必须在被分析项目外，并防止经链接覆盖源码，写入失败不得截断既有报告。源文件扫描前后的身份 / 内容指纹一致才可报告只读验证成立。

## 2026-10-27 本地封闭校验诊断

默认关闭，仅本地启动环境变量 CODEVIZ_CLOSED_VALIDATION_DIAGNOSTICS 精确为1时启用；无前端/桥接/模型开关，配置或授权不触发请求。每进程只捕获首个解释任务，总计最多两条：final/repair校验事实，以及至多一条ordinary/final/repair传输拒绝记录，共用同一个两条上限。仅固定码/布尔检查/饱和计数/有界位置，不保留模型原文、源码、ID、路径、密钥、异常消息或哈希，不重复解析原文。
固定应用缓存文件closed-validation-diagnostics.json，<=4096字节，启用启动清空，终态及资源释放后由容量一的私有worker落盘；拒绝非精确类型、额外字段、链接/reparse/非普通目标，失败安静丢弃，无重试/请求/公共错误。Windows pin目录并以CREATE_NEW源句柄写入及同父固定basename改名；POSIX用no-follow根目录描述符，避免路径替换重定向。不改ACL、不碰项目/源码/分析缓存/annotations；原解析/证据/预算/权限判断保持权威。无诊断记录不代表成功，原始payload不可作为调试fallback。详见批准的closed-validation-diagnostics计划。

N传输记录严格为phase/stage/reason三字段，reason只能为28个固定拒绝类别之一；首次实际守卫失败才生成私有不可变值，不读取异常消息猜原因。仅接受已加载SDK的精确异常类型及精确私有值，不引入SDK提前加载或新采集开关。已有原因可在后续超时/清理覆盖公开错误时保留，但不改变公开错误优先级；纯超时或纯清理失败没有猜测原因。资源未释放时不提前落盘，采集失败不改变原错误、预算或触发重试。公共DTO、前端和协议接受条件不变，见delta-rejection-reason计划。

## 项目解释的再次披露（2026-10-29）

项目分析和条目追问仍需要主动发送及当前服务商/精确文件授权。旧AI说明也是可能源于源码的内容，不能当作免费历史或用单个随意文件标签掩盖多文件来源。服务保留原任务全部可能已发送依赖的私有manifest，重用时逐项核验原owner、项目/分析/配置/授权及文件完整内容身份，并检查衍生文本本身的适用出站限制。

最多1000字符的解释以明确不可信数据进入请求；私有origin/标签不传给模型。其实际每次出现均纳入原字符与输入预算，依赖文件并入原文件上限，不通过猜来源、静默丢标签、覆盖计数或复制原receipt扩大权限。来源无法证明即拒绝；新事实必须重新读取并登记。取消、替换、原会话清空/淘汰和撤权均阻止晚到的解释提交，不重新绑定到新artifact。AI不修改源码、静态事实、用户文件树或注解。
