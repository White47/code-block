## Diagnosed failures and minimal harness changes

1. **Bootstrap timeout depends on the execution boundary.** Installed
   `webview/event.py` returns `self._event.wait(timeout)`, a bool. The None-return
   hypothesis is disproven. A minimal hidden native fixture initialized WebView2
   successfully inside the Codex sandbox, then received NavigationCompleted
   success=false / ConnectionAborted and stalled during bridge injection. The
   same fixture with controlled environment still failed there. Outside that
   sandbox, under approved execution with the same memory resources and guards,
   initialization, navigation, bridge injection and loaded completed. Changing
   hidden visibility handling or using about:blank also did not resolve the
   sandbox failure. The harness now records initialization/navigation evidence
   and loaded state. Its original 15-second loaded wait and 20-second component
   result wait remain mandatory. It does not silently retry outside the sandbox,
   fabricate loaded, or skip native verification.

2. **A separate browser bundle defect caused the component timeout after loaded.**
   Local module error capture revealed `ReferenceError: process is not defined`.
   The installed Vite implementation deliberately omits its default NODE_ENV
   replacements for library builds. The original in-memory library bundle retained
   `process.env.NODE_ENV`; jsdom in Node masked that dependency. A single-variable
   production substitution made the same native fixture pass. The harness build
   now explicitly defines only `process.env.NODE_ENV` as `"production"`, asserts
   that this unresolved reference is absent, and imports the same local bundle
   inside the entry's try/catch so import errors produce failure reports. No
   browser process shim, eval, remote loader or application config change was added.

3. **Clearing the environment removed Windows expansion inputs.** Regression
   tests first failed on missing SystemDrive in both the guard and child launch.
   Guard, Python children, freezer and native Node child now receive explicit
   SystemDrive=C:, SystemRoot=C:\Windows and PROGRAMDATA/profile/appdata/temp
   paths under task-specific build directories, with ambient secrets cleared.
   The pre-existing literal `%SystemDrive%/ProgramData` directory remains intact;
   its creation and last-write timestamps are 2026-10-12 14:04:48, consistent with
   the earlier probe but insufficient to prove exclusive ownership. Those
   timestamps were unchanged after the corrected source/freeze/native probes.
   No residual data was deleted, so it remains recoverable for ownership review.
